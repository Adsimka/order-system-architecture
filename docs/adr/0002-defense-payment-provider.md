# ADR-0002: Защита от деградации внешнего платёжного провайдера

- Status: Proposed
- Date: 2026-10-30
- Owners: Backend Team

## Context
Внешний платёжный провайдер может деградировать или быть полностью недоступным.   
Оплата происходит асинхронно через webhook, но есть два синхронных вызова к провайдеру: 
 - создание HHP-сессии (в API) 
 - запрос статуса (в Async Worker)

Без защиты медленные ответы провайдера могут исчерпать пулы потоков и привести к каскадному отказу всей системы.

## Decision
Использовать жёсткие таймауты и retry с backoff вместо полноценного Circuit Breaker:
- Таймауты: connect 1s, read 3s для всех вызовов к провайдеру
- Создание HHP-сессии: при таймауте или ошибке - быстрый отказ пользователю с 503 и сообщением "попробуйте позже", без retry
- Запрос статуса: retry с exponential backoff (1s, 2s, 4s, 8s, максимум 5 попыток), после чего перевод платежа в статус MANUAL_REVIEW_REQUIRED (Dead Letter Queue)
- Отдельные пулы HTTP-соединений для вызовов к провайдеру, чтобы изолировать их от внутренних вызовов

## Alternatives considered
1) Circuit Breaker (Resilience4j) с тремя состояниями (CLOSED/OPEN/HALF_OPEN) - даёт более тонкую защиту, но добавляет сложности (состояния, метрики, конфигурация), которая не оправдана при текущей нагрузке 55.5 RPS и размере команды 6-8 человек
2) Только retry без таймаутов - при деградации провайдера retry только усугубляют проблему, увеличивая время ответа
3) Только таймауты без retry - для worker'а это означает преждевременный перевод в MANUAL_REVIEW, для API приемлемо
4) Service mesh (Istio/Linkerd) - избыточная инфраструктура для текущих масштабов

## Consequences
- При деградации провайдера API быстро отказывает пользователям (p99 не раздувается), а не ждёт таймаут
- Worker корректно обрабатывает временные сбои через retry, а постоянные - через Dead Letter Queue
- Изолированные пулы соединений защищают внутренние вызовы монолита от проблем с провайдером
- Проще диагностировать и отлаживать по сравнению с Circuit Breaker
- При росте нагрузки или учащении деградаций провайдера можно добавить Circuit Breaker без изменения бизнес-логики
